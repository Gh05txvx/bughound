Burp Suite integration

BugHound finds candidate bugs; you validate them by hand in Burp Repeater. This integration bridges the two without switching tools, from the Burp side: an extension pulls findings from BugHound, then sends their request to Repeater.

BugHound finds → API /api/v1/findings → the “BugHound” tab in Burp → Repeater (Send manual)

Works in Burp Community You do not need Burp Pro yet: Repeater and loading a .jar extension yourself are available in Community. Pro is only needed for the active scanner, the full Intruder, or saving a project, none of which this flow requires.

Read-only & no auto-submit: the extension only reads from BugHound (GET), then loads the request into Repeater. Sending it to the target stays your manual action through the Send button.

1 · API BugHound (read-only)

The extension's data source. Auth is HTTP Basic with your BugHound account (GET, no CSRF needed). Without credentials → 401.

EndpointDescription
GET /api/v1/findings?program=<name>The findings of one program. Options: run_id, status, severity (comma-separated), include_duplicates=1.
GET /api/v1/findings/{id}One full finding (including evidence.request).

2 · Extension Burp (Montoya)

The source is in the repo: burp-ext/. Build once, load it into Burp.

Build
cd burp-ext
gradle shadowJar
# result: build/libs/bughound-burp.jar

Load: Burp → Extensions → Add → type Java → pick bughound-burp.jar. A BugHound tab appears.

Use: in the BugHound tab, fill in the BugHound URL ({{.BaseURL}}), user, pass and program name → Load findings → pick a row → Send to Repeater → press Send yourself to validate.

Prerequisites: JDK 17+ and Gradle 8+. Details and troubleshooting (the montoya-api version) are in burp-ext/README.md.

Security notes

  • The API is GET only: the extension does not change BugHound data, does not trigger scans, and never sends a request to the target automatically.
  • BugHound's egress / scope guard / rate limiter still govern BugHound's own scans; the extension sits outside that path (a read-only handoff → Repeater).
  • Scope during validation: Repeater sends wherever you press Send, so make sure the target is in scope for your bug bounty program. That is your responsibility in Burp, like any Repeater request.
  • Credentials live only in the extension's memory (not persisted). For a non-local BugHound, put it behind TLS so Basic auth does not travel in the clear.
